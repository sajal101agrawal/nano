# Features & Capabilities

A complete reference of what Nano does, organized by functional area.

---

## Public job board

| Feature | Description |
|---|---|
| Job listing | `/jobs` displays all open requirements with title, location, engagement type, and work mode |
| Job detail page | `/jobs/[slug]` shows full job description, client context, and the application wizard |
| Public slugs | Each requirement has a unique `public_slug` for shareable URLs |
| Closed role handling | Applications to closed or filled requirements are rejected with a clear error |

---

## Candidate application

| Feature | Description |
|---|---|
| Multi-step wizard | Six steps: upload, details, preferences, questions, submitting, done |
| CV upload | PDF and DOCX accepted, max size configurable via `MAX_CV_SIZE_MB` (default 10 MB) |
| Quick CV parse | On draft creation, Claude extracts name, email, and phone for form pre-fill |
| Draft persistence | Partial applications saved in `draft_applications`; resume via `?d=<id>&s=<step>` |
| Work preferences | Contract/full-time openness, notice period, locations, CTC, hourly rate |
| Screening questions | Per-requirement custom questions (text, select, boolean, multiselect) |
| Duplicate prevention | One application per candidate per requirement (unique constraint) |
| Suppression check | Applications from unsubscribed emails are rejected |
| Rate limiting | 10 applications per IP per hour |
| Confirmation email | Transactional email sent on successful submission |
| Admin notification | In-app notification created for new applications |

---

## Draft application recovery

| Feature | Description |
|---|---|
| Auto-save | Contact details and preferences saved via `PATCH /api/candidate/draft/[id]` |
| URL state | Draft ID and step reflected in query parameters for bookmarking |
| 15-minute reminder | Email sent if draft abandoned after 15 minutes |
| 6-hour reminder | Second reminder email after 6 hours |
| 7-day expiry | Stale drafts marked `expired` and cannot be resumed |
| Admin visibility | `/admin/drafts` shows incomplete applications and reminder status |

## CV parsing (AI)

| Feature | Description |
|---|---|
| Background processing | Full parse runs asynchronously via BullMQ after application submit |
| Text extraction | PDF via `pdf-parse`, DOCX via `mammoth` |
| Structured extraction | Claude `tool_use` with strict schema guarantees parse-safe JSON |
| Recruiter summary | 3–4 sentence professional summary generated by Claude |
| Skill denormalization | Skills stored in `candidate_skills` with trigram index for search |
| Vector embedding | OpenAI embedding stored on `candidate_profiles.embedding` |
| Versioning | New profile version per application; `is_current` flag on latest |
| Re-parse | Admin can trigger `POST /api/admin/candidates/[id]/cv-reparse` |
| Failure handling | Failed parses notify admins; `review_required` for low-confidence extractions |
| Status tracking | Application status: `applied` → `parsing` → `parsed` / `parse_failed` |

## AI matching

| Feature | Description |
|---|---|
| Semantic search | HNSW cosine similarity over candidate embeddings |
| Rule-based scoring | Adjusts for availability, contract preference, experience |
| Claude re-ranking | Top 20 candidates re-scored with rationale |
| Applicant guarantee | All applicants included in match results regardless of vector rank |
| Pool-wide matches | `matches` table stores scores for entire candidate pool per requirement |
| Manual shortlist | Recruiters can add/remove candidates from shortlist via API |
| Auto-trigger | Match job enqueued after CV parse and on requirement creation |
| Manual trigger | Admin can re-run matching from requirement detail page |

### Scoring formula

```
combined_score = (vector_score × 0.6 + rule_score × 0.4) × 100
```

Rule penalties: unavailable (×0.1), unknown availability (×0.6), not open to contract when required (×0.3).

## Availability tracking

| Feature | Description |
|---|---|
| One-click confirmation | Token links in email: available / unavailable |
| Admin-triggered checks | Send availability email from candidate detail page |
| Bulk cron | Daily at 9am UTC — pings idle candidates (up to 50 per run) |
| Token expiry | Hourly cron expires unused tokens after `AVAILABILITY_TOKEN_EXPIRY_DAYS` |
| Status sync | Candidate `availability_status` updated on response |
| Application default | New applicants marked `available` on submit |

## Application pipeline

Status lifecycle for applications:

```
applied → parsing → parsed → shortlisted → contacted → in_discussion → offered → placed
                 ↘ parse_failed
                                    ↘ rejected
                                    ↘ withdrawn
```

Admins update status from requirement detail or application views.

## Email & outreach

| Feature | Description |
|---|---|
| Three streams | `transactional`, `availability`, `outreach` — different from addresses |
| Template system | `{{variable}}` substitution; conditional `{{#if}}` blocks |

| Suppression list | Unsubscribes, bounces, complaints block future sends |

## External sourcing (Apollo.io)

| Feature | Description |
|---|---|
| People search | Search by skills, title, location, seniority |
| Result persistence | Prospects upserted to `prospects` table |
| Email enrichment | Apollo People Match API reveals personal email (synchronous) |

## Analytics

Dashboard metrics via `GET /api/admin/analytics`:

- Candidate pool stats (total, active, last 30 days)
- Availability breakdown (available / unavailable / unknown)
- Application funnel by status
- Requirements by status
- Email delivery stats
- Weekly candidate growth (12 weeks)
- Top 15 skills in the pool

## Background processing

| Queue | Purpose |
|---|---|
| `cv-parse` | Full CV pipeline (concurrency: 3) |
| `email` | Send queued emails (concurrency: 10) |
| `match` | AI matching for requirements (concurrency: 2) |
| `availability` | Token send, expiry, bulk checks (concurrency: 5) |
| `draft-reminder` | Abandonment emails and stale expiry (concurrency: 1) |

See [Worker & Queues](worker.md) for cron schedules and processor details.

## Notifications

- CV parse failures
- Availability status changes
- Email replies
- System events
